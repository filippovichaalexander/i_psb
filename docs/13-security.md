# Безопасность: модель угроз и меры

## 1. Что защищаем

- Музыкальную библиотеку и конфиги на SD.
- Пароли Wi-Fi (`/config/wifi.json`).
- Прошивку (целостность OTA).
- Слух пользователя (ограничение громкости) — тоже безопасность.

## 2. Кто угрожает

| Угроза | Реалистичность | Влияние |
|---|---|---|
| Случайный человек в радиусе AP | Высокая (если пароль слабый) | Кража/удаление файлов, просмотр логов |
| Вредоносный файл (ID3/имя) | Средняя | Crash, порча библиотеки |
| Кража устройства | Средняя | Доступ к файлам/паролям Wi-Fi |
| Подмена прошивки | Низкая, но критичная | Выполнение чужого кода |
| Supply chain (библиотеки) | Средняя | Компрометация сборки |

## 3. Дефолты (обязательные)

- **Никакого `12345678`.** Уникальный WPA2-пароль на устройство, генерируется
  при первом boot из TRNG, показывается на EPD, хранится в NVS.
- Веб-API: токен для destructive-операций; токен — на экране.
- BLE: bonding/passkey; без pairing — только read-only статус (или ничего).
- OTA: пароль + SHA-256 + подпись; rollback при несоответствии.
- Логи не содержат паролей/токенов. Wi-Fi пароль не логируется.

## 4. Меры по слоям

### Прошивка

- Проверка границ при парсинге ID3/UTF-8 (unit-тесты).
- Не доверять именам файлов; sanitize.
- WDT + coredump; не «зависать» на ошибке.
- FreeRTOS: очереди фиксированного размера, без `String` в audio.
- OTA only в `app1`, health-check после reboot.

### Wi-Fi/HTTP

- AP: WPA2, уникальный пароль, скрытие SSID не является защитой.
- STA: пароль в NVS; не отдавать в API.
- HTTP: whitelist путей, лимит размера, rate limit, same-origin.
- Upload: потоковая запись, проверка свободного места, atomic rename.
- Логи: доступ только с токеном.

### BLE

- NimBLE: pairing + bonding, passkey; отключаемо в настройках.
- Не отдавать файловую систему; только команды/метаданные.
- Ограничить размер обложки; проверять CRC.

### Физическая

- Корпус закрывается винтами, не клеем; pogo/BOOT внутри.
- Li-Po с protection board; предохранитель/полимер по питанию (опция).
- Не оставлять на солнце; вентиляция у TP4056.

### Supply chain

- Pin versions, Docker, CI.
- Dependabot для GitHub Actions.
- Проверять новые библиотеки; не тянуть случайные форки.
- Релизные артефакты — из CI, не с ноутбука.
